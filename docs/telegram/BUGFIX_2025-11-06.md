# Critical Bug Fix: Premature Approval Confirmations

**Date**: 2025-11-06 02:15 UTC
**Severity**: Critical
**Status**: ✅ Fixed

---

## Executive Summary

A critical bug in the Telegram notification system was causing false "APPROVED" messages to be sent immediately after approval requests, without waiting for actual user approval.

---

## The Bug

### Symptom
Users received approval confirmation notifications **before** approving commands:

```
[02:10] 🔴 APPROVAL NEEDED
        Check staging health endpoint
        `curl -sI https://...`

[02:10] 🟢 APPROVED          ← Sent immediately (BUG!)
        Check staging health endpoint
        `curl -sI https://...`
```

**User Experience**: "I did not approve this, but I received notification that I had approved of it"

### Root Cause

**File**: `.claude/bash-approval-notifier-v2.sh`
**Issue**: PreToolUse hook was sending BOTH notifications in sequence:

```bash
# Line 114: Send approval request
"$NOTIFY_SCRIPT" "$MESSAGE"

# Lines 122-135: Immediately send confirmation (WRONG!)
echo "🟢 APPROVED ..." > "$MSG_FILE"
send_confirmation.sh "$MSG_FILE" &
```

The hook runs **before** the user makes a decision, so the confirmation was premature.

---

## The Fix

### Solution: Two-Hook System

Split the notification logic into two separate hooks:

#### 1. PreToolUse Hook (`bash-approval-notifier-v2.sh`)
**Runs**: Before command execution
**Action**: Sends 🔴 APPROVAL NEEDED only

```bash
# Send approval request
MESSAGE="🔴 *APPROVAL NEEDED*
━━━━━━━━━━━━━━━━━━
📋 $DESCRIPTION
\`$COMMAND\`
⏱ *Waiting for approval...*"

"$NOTIFY_SCRIPT" "$MESSAGE"
# NO confirmation sent here!
```

#### 2. PostToolUse Hook (`bash-post-execution-notifier.sh`) - NEW
**Runs**: After command execution
**Action**: Sends 🟢 APPROVED & EXECUTED

```bash
# Only runs if command was approved and executed
MESSAGE="🟢 *APPROVED & EXECUTED*
━━━━━━━━━━━━━━━━━━
📋 $DESCRIPTION
\`$COMMAND\`"

"$NOTIFY_SCRIPT" "$MESSAGE"
```

### Configuration Update

**File**: `.claude/settings.json`

```json
{
  "hooks": {
    "PreToolUse": [{
      "matcher": "Bash",
      "hooks": [{
        "type": "command",
        "command": "/home/runner/workspace/.claude/bash-approval-notifier-v2.sh",
        "timeout": 2
      }]
    }],
    "PostToolUse": [{          // ← NEW
      "matcher": "Bash",
      "hooks": [{
        "type": "command",
        "command": "/home/runner/workspace/.claude/bash-post-execution-notifier.sh",
        "timeout": 2
      }]
    }]
  }
}
```

## Correct Behavior Now

### Approval Flow

```
1. Command needs approval
   ↓
2. PreToolUse hook runs
   ↓
3. 🔴 APPROVAL NEEDED sent to Telegram
   ↓
4. Claude Code waits for user approval
   ↓
5. User clicks "Approve" or "Deny"
   ↓
6. If approved: Command executes
   ↓
7. PostToolUse hook runs
   ↓
8. 🟢 APPROVED & EXECUTED sent to Telegram
```

### Pre-Approved Commands

```
1. Command is pre-approved
   ↓
2. PreToolUse hook: No notification (silent)
   ↓
3. Command executes immediately
   ↓
4. PostToolUse hook: No notification (silent)
```

## Lessons Learned

### What Went Wrong

1. **Insufficient Testing**: Bug not caught during initial implementation
2. **Misleading Hook Name**: "PreToolUse" suggests it runs before approval, but confirmation was sent anyway
3. **Single Hook Limitation**: Tried to handle both request and confirmation in one hook

### Best Practices Applied

1. **Separation of Concerns**: Split into two hooks with clear responsibilities
2. **Hook Timing**: PreToolUse for requests, PostToolUse for confirmations
3. **Consistent Logic**: Both hooks use same pre-approved list
4. **User Feedback**: Bug reported by user, fixed within 30 minutes

### Code Review Checklist

For future notification system changes:

- [ ] Test with non-pre-approved command
- [ ] Verify approval required before confirmation
- [ ] Check both PreToolUse and PostToolUse logic
- [ ] Confirm pre-approved commands are silent
- [ ] Test denial flow (no confirmation sent)

### Monitoring

Watch for these patterns in logs:
- Confirmations without approval actions
- Duplicate notifications
- Out-of-order notifications

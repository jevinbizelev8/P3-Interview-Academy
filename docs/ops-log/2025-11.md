### Technical Challenges & Solutions

#### Challenge 1: PDF Parsing Native Dependencies

**Problem**: pdf-parse@2.4.5 depends on @napi-rs/canvas (Rust native addon)
- Requires: Rust compiler, gcc, g++, cairo, pango, pixman, libjpeg
- AWS EB: Doesn't have these build tools pre-installed
- Result: npm install fails during deployment

**Solution**: Mozilla pdfjs-dist (legacy build)
- 100% pure JavaScript
- No Canvas/DOM dependencies in legacy build
- Battle-tested (powers Firefox PDF viewer)
- 8M downloads/week

**Lessons Learned**:
- Always check for native dependencies before adding npm packages
- Test deployment on AWS EB staging before production
- Have fallback libraries researched in advance
- Legacy builds exist specifically for Node.js environments

#### Challenge 2: Browser Globals in Node.js

**Problem**: pdfjs-dist default build accesses DOMMatrix, Canvas at module load
- Node.js doesn't have these browser globals
- App crashes on startup: `ReferenceError: DOMMatrix is not defined`

**Solution**: Dynamic import + legacy build
```typescript
// Dynamic import defers loading until function call
const pdfjsLib = await import('pdfjs-dist/legacy/build/pdf.mjs');
```

**Lessons Learned**:
- Use dynamic imports for browser-dependent libraries
- Legacy builds are specifically designed for Node.js
- Test server startup after adding new dependencies

### Technical Context

#### Why Feature Branch Deployments Bypass Tests

**GitHub Actions Workflow**: `.github/workflows/deploy-eb-staging.yml`

**Triggers**:
- Pull request events to `main`
- Workflow dispatch (manual trigger)

**Behavior**:
- Feature branch PR → Deploy to staging directly
- Main branch push → Run tests → Deploy to staging → Approval gate → Production

**Result**:
- Feature branches can deploy to staging even with failing tests
- Main branch requires all tests to pass
- This is a **safety feature**, not a bug

**Multi-Gate System**:

```
    ↓
Build Application
    ↓
Deploy to Staging
    ↓

    ↓
Manual Approval Gate (Founder)
    ↓
Deploy to Production
```

# Authentication Fix - 2025-11-10

## Problem Summary

**Status**: ✅ Fixed in staging, awaiting final deployment and testing

**Issue**: Login and signup endpoints returning 500 errors on staging environment
- `/api/auth/login` - Returns `{"message":"Login failed"}` (HTTP 500)
- `/api/auth/signup` - Returns `{"message":"Registration failed"}` (HTTP 500)

**Impact**: Complete authentication failure - users cannot login or register

---

## Root Cause

**Database Schema Mismatch**: Staging database missing 20 columns that exist in the application code schema (`shared/schema.ts`).

**Error from logs**:
```
❌ LOGIN ERROR: error: column "full_name" does not exist
   at async file:///var/app/current/node_modules/drizzle-orm/node-postgres/session.js:83:22
  severity: 'ERROR',
  routine: 'errorMissingColumn'
```

When `storage.getUserByEmail()` is called, Drizzle ORM tries to SELECT all columns defined in the schema, including `full_name`. This column didn't exist in staging database, causing PostgreSQL to throw an error.

**Why test-seed worked**: The `/api/auth/test-seed` endpoint uses raw SQL queries instead of Drizzle ORM, bypassing the schema column requirements.

## Solution Implemented

### 1. Schema Migration Endpoint

**Created**: `/api/auth/fix-schema` endpoint in `server/auth-simple.ts`

**Purpose**: Add missing columns to the users table via HTTP endpoint (since direct database access from Replit is blocked by security groups)

**Security**: Protected by `TEST_SEED_KEY` header (same as test-seed endpoint)

**How it works**:
- Iterates through all 20 missing columns
- Uses `ALTER TABLE users ADD COLUMN IF NOT EXISTS ...` for each
- Handles SQL reserved keywords (e.g., `current_role`) with quoted identifiers
- Returns detailed results for each column operation

### 2. Implementation Details

**File**: `server/auth-simple.ts` (lines 185-246)

**Key features**:
- Idempotent (can run multiple times safely)
- Handles existing columns gracefully
- Reports success/failure for each column
- Supports reserved keyword quoting

## Technical Notes

### Why Direct db:push Failed
Attempted to run `npm run db:push` from Replit, but connection timed out:
```
Error: connect ETIMEDOUT 54.251.218.151:5432
```

**Reason**: Replit cannot connect directly to AWS RDS due to security group restrictions (database only allows connections from EB instances and whitelisted IPs).

**Solution**: Created HTTP endpoint to run migrations from within the staging environment (which has database access).

### Why This Approach Works
1. **Security**: Endpoint is protected by TEST_SEED_KEY (staging only)
2. **Idempotent**: Uses `ADD COLUMN IF NOT EXISTS` - safe to run multiple times
3. **Observable**: Returns detailed results for each column operation
4. **Temporary**: Can be removed after schema is fixed

### Schema Audit on Startup
The application runs `ensureCriticalSchema()` on every server start (see `server/index.ts` line 75 and `server/services/schema-auditor.ts`). This creates missing tables but **does not add missing columns** to existing tables - that's why this manual migration was needed.
